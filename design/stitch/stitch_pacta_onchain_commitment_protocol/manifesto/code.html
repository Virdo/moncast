01. Protocol Architecture

How it Works

Secure Formulation

Users define commitments locally. Data remains encrypted on the client device, never exposing raw objectives to the public ledger.

STEP_02

ZK-TLS Proof Generation

Web sessions are converted into cryptographic proofs using ZK-TLS 1.3, verifying API responses from web2 data sources without breaking encryption.

Onchain Settlement

Smart contracts verify the ZK-proof. If valid, the commitment is marked complete, releasing bonded assets or triggering programmed yields.

03. Protocol Specifications

Frequently Asked Questions

How does PACTA guarantee data privacy? expand_more
PACTA utilizes Zero-Knowledge Transport Layer Security (ZK-TLS) 1.3. This means we generate cryptographic proofs of your interactions with external data sources (like APIs) without ever seeing or storing the actual data. The blockchain only records a true/false verification of your commitment.
What happens if the underlying API changes? expand_more
We maintain a robust Oracle network that tracks API schema changes. If a provider alters their endpoints significantly, commitments are gracefully paused, and users are given a grace period to update their proving scripts without penalty.
How fast is the onchain settlement? expand_more
Settlement occurs instantly upon the verification of the ZK-proof by our smart contracts. Depending on network congestion on the underlying L2, finality is typically reached within seconds.
